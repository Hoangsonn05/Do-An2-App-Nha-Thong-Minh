- Dự án: SmartHomeAI (`com.example.smarthomeai`), Firebase `appaintm` (`883290202549`), RTDB `asia-southeast1`

## 1. Phạm vi

**Trong B1:** audit RTDB hiện có (read-only) → Rules (JSON thuần + `build-rules.mjs`) + 54 Emulator tests → RTDB SDK + Coroutines `1.8.1` → `FirebaseProvider` → `CloudRepository` (3 hàm) → `RtdbPaths` + `RtdbPayloadBuilder` → `RtdbCloudRepository` → `FakeCloudRepository` → test → nghiệm thu.

**API tối thiểu:**
```kotlin
interface CloudRepository {            // thuần Kotlin, không import Firebase
    fun observeHomes(): Flow<CloudResult<List<CloudHome>>>
    suspend fun createHome(name: String): CloudResult<String>   // trả homeId
    fun observeMembers(homeId: String): Flow<CloudResult<List<CloudMember>>>
}
```
Không tạo path ghi thử (`diagnostics`/test node) trong dữ liệu Home hay trên production. Nếu ở phase sau (B2+) cần theo dõi trạng thái kết nối SDK, dùng `.info/connected` (read-only); `.info/connected` **hoãn sau B1**, không đưa vào interface 3 hàm của B1.

**Ngoài B1 (không làm, không chuẩn bị code):** Gateway/Telemetry/Event Sync, Remote Command, Device ACK, Invitation, QR pairing, UI đa-Home đầy đủ, đọc/ghi `users/{uid}` ở Android, `.info/connected`, FCM, App Check enforcement, firmware, cơ chế dọn lịch sử, `CloudMapper`.

**LOCKED (không sửa):** `Esp32Client.kt`, `esp32/**` (`SmartHomeESP32.ino`, `wifi_config.example.h`, …), `AuthRepository.kt`, `Storage.kt`, `SmartHomeViewModel.kt`, `MainActivity.kt`, `ui/**`, `app/google-services.json`, endpoint & JSON protocol, mọi thứ `VERIFIED-HW`.

Ranh giới: `UI → ViewModel → Repository → Cloud` | `Android → Esp32Client → ESP32`. Cloud không phụ thuộc `Esp32Client`; Firebase SDK không vào ViewModel; `CloudRepository` không thay Local Storage, không là đường điều khiển LAN.

**1.2 Rules (`cloud-rules/`)**
- Soạn `cloud-rules/database.rules.src.json` là **JSON thuần hợp lệ** (không có comment `//` hay `/* */`, không JSONC, không chuỗi nhiều dòng, không stub placeholder; `state/device` viết đầy đủ) theo đúng B0 §8.4, bao gồm:
  - `@ACTIVE` tại `commands/$cmdId/status/.write` (F6 — thống nhất chính sách thiết bị `revoked` không được ghi dữ liệu, kể cả hủy lệnh).
  - Chính sách `revoked` một chiều (terminal) tại `devices/$deviceId/status/.validate` (F9 — cấm chuyển `revoked → active`).
  - `users/{uid}/updatedAt` giữ nguyên là **optional** (F3 — partial update có thể không làm mới `updatedAt`, `.validate` không chạy khi xóa child và sibling `.validate` không bảo đảm chạy khi cập nhật child khác).
- Soạn `cloud-rules/build-rules.mjs`:
  1. Parse `database.rules.src.json` bằng `JSON.parse()`.
  2. Mở rộng token đã bọc ngoặc `(...)` theo đúng thứ tự **token ghép (`@MEMBER`, `@DEVICE`) trước token cơ sở (`@OWNER`, `@ACTIVE`, `@AUTH`)**, hoặc lặp tới điểm bất động (tối đa 5 vòng), **bắt buộc dùng callback replacer `() => replacement`** (F9) để tránh `$homeId`/`$deviceId` bị diễn giải sai.
  3. Kiểm tra không còn khớp regex `/@[A-Z]+/` (nếu còn → thoát mã lỗi khác 0).
  4. Xác nhận output là JSON thuần bằng `JSON.parse()` rồi ghi ra `cloud-rules/database.rules.json`.
  5. Bổ sung unit test `cloud-rules/test/build-rules.test.mjs` xác minh JSON parse và token expansion.
- Phạm vi ruleset B1: bao gồm `users`, `userHomes`, `homes/{h}/{meta,members}` cùng `devices` và `deviceData`.
- Phân biệt rõ **8 core runtime assumptions** (`EMU-1..8` ở B0 §8.4, tách riêng create-only và multi-path delete, kèm fallback cho `hasChildren()` và live listener revocation) và **12 hàng kiểm chứng Emulator bắt buộc** ở bước 1.3; **sửa Rules theo kết quả Emulator, không nới Rules để làm test xanh**; không ghi Emulator PASS trước khi chạy thực tế.

**1.3 Emulator & Rules Test Suite (`cloud-rules/`)**
- `cloud-rules/package.json`: `firebase-tools`, `@firebase/rules-unit-testing`, `firebase` (modular), runner `node --test`, script `build:rules`, `test:build`, `test:rules` gọi `node scripts/run-emulator.mjs` (F7 — tương thích Windows, không dùng inline `JAVA_HOME=...`).
- `cloud-rules/scripts/run-emulator.mjs`: đặt `JAVA_HOME` (qua env var cấu hình hoặc fallback `D:\Program Files\Android Studio\jbr`), thêm `%JAVA_HOME%\bin` vào `PATH`, spawn Firebase Emulator với `--project demo-smarthomeai --only database`, chuyển tiếp exit code và xử lý lỗi/signal sạch sẽ.
- `cloud-rules/firebase.json`: chỉ khai báo `database.rules` (`database.rules.json`) và emulator `database` (host `127.0.0.1`, port `9000`); không khai báo deploy target/hosting thật, không đặt `.firebaserc` trỏ `appaintm`.
- Quy chuẩn test suite (`cloud-rules/test/rules.test.mjs`, F1/F2/F5/F6/F8/F9):
  - Tách test độc lập với `beforeEach` reset database + seed chuẩn (bắt buộc cho #36, #39, #42, #47, #52 và mọi test DENY).
  - Mỗi test ghi rõ: Pre-state, Request path, Payload, Expected result, Điều kiện Rules mục tiêu.
  - Sửa đường đi DENY theo F2: #25 dùng device mới `dev_D4002` chưa có `deviceAuthUid`; #30 tách điều kiện `receivedAt` cho `uA` và bổ sung partial-write `state/device`; #45 dùng fixture đúng (`uB` ghi `_g` với `source: 'device'`, `dev1` ghi `_d` với `source: 'gateway'`); #49 xóa đúng leaf `$recordId`/`$eventId`; #51 seed sẵn `dev_D3001/commands/cmd_30001`; #53 payload event đầy đủ mới tại `events/g_s7_...` kèm field thừa `deviceKey`; #13 & #23 dùng `createdAt` quá khứ.
  - Bổ sung F5 positive read cho Owner & Member (`config`, `telemetry`, `commands`, `acks`, `events`) và query/`.indexOn` (`events` theo `receivedAt`, `commands` theo `createdAt`, `telemetry` theo `orderByKey().limitToLast(n)`).
  - Bổ sung F1 live listener revocation (`PERMISSION_DENIED`), F3 `users/{uid}/updatedAt` partial update/delete, F6 cancel command trên active vs revoked device, F9 `revoked → active` DENY.
  - Ghi rõ tổng số test chạy thực tế từ runner (không dùng số hàng thiết kế thay cho số test đã chạy) và lưu đủ 12 hàng verification + log vào `docs/p1-1-b1/rules-test-report.txt`.

| File | Nội dung & Hợp đồng bắt buộc |
|---|---|
| `CloudModels.kt` | `enum class CloudRole(val wireValue: String) { OWNER("owner"), MEMBER("member") }` (kèm `fromWire(String?)`); `data class CloudHome(val id: String, val name: String, val role: CloudRole)`; `data class CloudMember(val uid: String, val role: CloudRole, val addedAt: Long? = null, val addedBy: String? = null)`; `sealed class CloudResult<out T>` với `Ok(data)`, `Err(error: CloudError, message: String? = null)`, `Unavailable`; `enum class CloudError { Unauthenticated, PermissionDenied, NotFound, Conflict, Offline, Timeout, InvalidData, Unknown }`; hằng số `const val CLOUD_OPERATION_TIMEOUT_MS: Long = 10_000L` |
| `CloudRepository.kt` | Interface 3 hàm (`observeHomes`, `createHome`, `observeMembers`); thuần Kotlin, không import Firebase |
| `RtdbPaths.kt` | Hàm thuần dựng đường dẫn RTDB (`userHomesPath`, `userHomePath`, `homeMetaPath`, `homeMembersPath`, `homeMemberPath`), kiểm tra key format `^[A-Za-z0-9_-]{8,64}$`, và từ chối ký tự RTDB cấm `/ . # $ [ ]` trên mọi UID / path segment (F10) |
| `RtdbPayloadBuilder.kt` | Hàm thuần dựng map payload cho `createHome` (`buildHomeMetaPayload`, `buildOwnerMemberPayload`, `buildUserHomeRoleValue`) nhận `timestampValue: Any` (production truyền `ServerValue.TIMESTAMP`, JVM test truyền sentinel); **`trim()` `name` trước khi validate & ghi**, từ chối `isBlank()`, kiểm tra độ dài 1–60, cấm `'deviceKey'`, kiểm tra UID không chứa ký tự RTDB cấm, ép `schemaVersion = 1` (F4, F10) |
| `CloudErrorMapper.kt` | Hàm thuần map lỗi Firebase → `CloudError`; có overload `mapDatabaseErrorCode(code: Int): CloudError` độc lập với constructor `DatabaseError` để unit test JVM trực tiếp, kèm `mapDatabaseError(DatabaseError)` và `mapException(Throwable)` (chỉ chuyển `TimeoutCancellationException` → `CloudError.Timeout`, không nuốt các `CancellationException` khác) (F4) |
| `RtdbHomeMerger.kt` | Pure Kotlin merge helper cho `observeHomes()`: đầu vào rỗng trả `CloudResult.Ok(emptyList())`; nguồn xác định role từ `meta.ownerUid == currentUid` (`OWNER`) hoặc `MEMBER` (chỉ hiển thị các Home đọc được `meta`, không tin mù chỉ mục `userHomes`); cô lập lỗi `PERMISSION_DENIED` / `NotFound` của Home lỗi thời mà không làm sập danh sách Home còn lại; phân biệt lỗi vận chuyển/tổng thể (`Offline`/`Timeout`/`Unknown` → `CloudResult.Err`) với lỗi quyền riêng lẻ (F4, N7) |
| `FirebaseProvider.kt` | Nhận `Context`; kiểm tra `FirebaseApp.getApps(context).isNotEmpty()`; đọc URL RTDB từ `FirebaseApp.getInstance().options.databaseUrl` (**không hardcode URL** nếu cấu hình Firebase đã cung cấp, không tự khởi tạo/sửa file locked); **khởi tạo lười**, **không gọi `setPersistenceEnabled(...)`**; trả `Unavailable` khi chưa cấu hình hoặc thiếu URL (F4) |
| `RtdbCloudRepository.kt` | `callbackFlow` bọc `ValueEventListener`, `awaitClose` gỡ listener (**không** bọc observer bằng `withTimeout`); thao tác suspend dùng `withTimeout(CLOUD_OPERATION_TIMEOUT_MS)` và chỉ chuyển `TimeoutCancellationException` thành `CloudError.Timeout` (ném lại `CancellationException` khác); dùng `RtdbPaths` + `RtdbPayloadBuilder` + `CloudErrorMapper` + `RtdbHomeMerger`; `createHome(name)` ghi tuần tự `meta` → `members/{me}` → `userHomes/{me}/{h}` |

## 6. Xử lý khi RTDB Rules không kiểm soát được một yêu cầu (theo kết quả Emulator)

| Yêu cầu `[EMU]` | Nếu Emulator chứng minh không đạt | Phương án (cần duyệt, không nới quyền) |
|---|---|---|
| `now` với `ServerValue.TIMESTAMP` | Kiểm tra lại cấu trúc payload/multi-path; nếu SDK/Rules có giới hạn thực tế, ghi nhận và đề xuất phương án duyệt trước khi đổi rule | Không tự bỏ ràng buộc khi chưa duyệt |
| `data.parent()` trong `.write` của `commands/$cmdId/status` | Thay bằng đường dẫn tường minh `root.child('homes').child($homeId).child('deviceData').child($deviceId).child('commands').child($cmdId).child('createdBy').val() === auth.uid` (cùng mức bảo mật) | Chạy lại 54 test |
| `.validate` node cha khi ghi một phần node con | Nếu không chặn được ghi một phần như kỳ vọng → chuyển `.write` xuống mức khóa yêu cầu ghi nguyên khối hoặc đánh giá lại mô hình node; **STOP báo cáo** | Cần duyệt kiến trúc |
| Create-only khi ghi trùng | Chấp nhận `PERMISSION_DENIED` khi trùng; client đọc kiểm tra trước | Đã có trong thiết kế |
| Phép nối chuỗi với số (`'g_' + stream + '_' + seq`) hoặc `% 1 === 0` | Rút gọn điều kiện `$eventId === ...` về regex `$eventId` + `source` khớp prefix + **giữ nguyên** ràng buộc chặt trên `stream` (`^[A-Za-z0-9]{1,16}$`) và `seq` (`>= 0 && <= 9999999999`) | Chạy lại 54 test |
| Multi-path delete `members` + `userHomes` (`EMU-5`) | Nếu có xung đột đánh giá rule → xóa tuần tự `members/{uid}` trước (thu hồi quyền ngay), rồi `userHomes/{uid}/{h}` | `observeHomes()` đã cô lập lỗi `PERMISSION_DENIED` |
| Live listener revocation (`EMU-6`) | Nếu listener đang mở trên Emulator/SDK không tự phát `PERMISSION_DENIED` tức thời khi mất quyền → ghi nhận rõ giới hạn thực tế, không giả định auto-revoke tức thời; lớp repository chủ động detach/re-validate listener khi có sự kiện thu hồi hoặc reconnect | Ghi log kết quả thực tế + không nới quyền |
| `newData.hasChildren()` không tham số (`EMU-8`) | Nếu Emulator không từ chối scalar bằng `newData.hasChildren()` → thay bằng `!newData.isString() && !newData.isNumber() && !newData.isBoolean()` kết hợp kiểm tra child hợp lệ | Chạy lại toàn bộ test Emulator |
| Không chống được giá trị khóa bí mật thật trong chuỗi tự do | Không thể bằng Rules (L6) | Schema chặt + `RtdbPayloadBuilder`/`CloudMapper` whitelist + test JVM/grep |
| Trở ngại nghiêm trọng, có bằng chứng, khiến RTDB không thể đáp ứng | — | **Báo cáo và dừng**; không tự đổi quyết định RTDB-only |
